1What it is30 s

My project is called Kerbside. It takes video from one fixed camera beside a road and measures every vehicle that passes: how many there are, how fast each one is going in kilometres per hour, which lane it is in, its size class, and its colour.

The rule I set myself was that it uses only classical image processing. There is no neural network or machine learning anywhere in the pipeline.

The live console playing the free_flow clip, with boxes and speed labels.

2The key idea45 s

A normal system recognises a car by how it looks, using a trained network. Mine recognises it by how big it is in real metres.

You click four corners of a rectangle of known size on the road, and from those four points the system computes a homography: an exact mapping between pixels in the image and metres on the road. After that, position is in metres, so speed is just distance divided by time, and a 4.5-metre object is a car while an 11-metre one is a bus. No training data is needed at all.

Calibration → Measure a distance, and tap across one lane: about 3.5 m.

3How it works45 s

The pipeline has nine stages. It learns what the empty road looks like, finds whatever differs from it, removes cast shadows using colour, and separates the pixels into individual vehicles with morphology, sized for how far each one is from the camera. Then it tracks each vehicle, counts it at a counting line, and measures its speed two independent ways: from its position, and from how its texture moves between frames.

Every stage is explainable. The interface shows each stage's output, the syllabus unit it uses, and the reason it exists.

The Pipeline view, scrolling through the stage outputs.

I set eight measurable targets before writing any code, and I haven't changed any of them since. Five were met and three weren't. Calibration is accurate to half a percent, but detection and speed fall short.

The three misses share one cause, and I proved it: the detection step sometimes splits one vehicle into two pieces, like a roof and a bumper. When I re-ran the same scene with shadows switched off entirely, accuracy barely changed, so shadows weren't the problem. The speed method that doesn't depend on the vehicle's outline is twice as accurate, which confirms the diagnosis.

5Close15 s

It runs live in the browser, with the real Python code, and it's a measuring tool, not a speed camera: it never labels anything a violation and never reads number plates. Thank you. I'm happy to show any part of it in more detail.

?If they ask one question

Why not use a neural network like YOLO?
It would detect better, but it answers a different question. The course is classical image processing, and here the geometry does the detector's job: a vehicle is classified by its size in metres, not by how it looks.
Why is accuracy below the targets?
One named cause: the detection step splits a vehicle into pieces. Tuning the later stages barely changed anything, which is how I know the fix belongs in segmentation.
Is it live or a recording?
Live. Change a setting and the whole pipeline re-runs on the device. The traffic comes from a built-in simulator, which is what gives exact accuracy figures: every true speed is known.
